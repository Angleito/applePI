# applePI — Gas City + Pi Multi-Agent Harness

Terminal-first hierarchical multi-agent software development harness.
Gas City owns orchestration; Pi is the reasoning runtime; Amos (planned)
handles Worker → Scout spawning.

```text
HUMAN
  │  interactive conversation (only with Executive)
  ▼
EXECUTIVE (Pi, named session, always on)
  │  gc session submit
  ▼
MANAGER   (Pi, one per workstream, rig-scoped)
  │  durable Gas City work (beads + sling)
  ▼
WORKER    (Pi, elastic pool, rig-scoped)
```

Five roles only: Human, Executive, Manager, Worker, Scout. This milestone
implements Human, Executive, Manager, Worker. Scout is planned (Phase 5).

## Current implementation

```text
agents/
  executive/   agent.toml + prompt.template.md   (deepseek-v4-pro)
  manager/     agent.toml + prompt.template.md   (deepseek-v4-pro)
  worker/      agent.toml + prompt.template.md   (deepseek-v4-flash)

UPSTREAM.md    upstreams, pins, prerequisites
tests/         integration tests (phase0-hierarchy, recovery)
```

- Beads backend: **bd** (Dolt) — Gas City's default. `file` is not usable
  for autonomous work claiming (gastownhall/gascity#1761).
- System packs: canonical v1.4.1 imports (`core`, `bd`) generated by
  `gc init`; see `pack.toml`.
- `scratch-proj` is a **Phase 0 development fixture** (a throwaway test
  project), not the final project-routing design. Rig-generic Manager and
  Worker templates are planned (Phase 0B).
- Worker pool is **0..1** until automatic worktree isolation is validated.

## Quickstart

```bash
# prerequisites — see UPSTREAM.md
gc version      # 1.4.1
pi --version    # >= 0.84
bd version
dolt version

# city bootstrap (once, or re-run after a fresh clone)
gc init . --template minimal --default-provider pi --skip-provider-readiness --no-start
gc import install
gc start

# register the Phase 0 fixture project as a rig
gc rig add ~/Projects/scratch-proj --name scratch-proj

# attach to the Executive (the Human's only interface)
gc session attach executive
```

`gc init` rewrites `city.toml`/`pack.toml` from its canonical templates —
run it before editing anything in a fresh clone.

## Worker claim flow

```bash
# a Manager (working in the rig) routes a task
gc sling scratch-proj/worker "<task with REPORT_TO / OBJECTIVE / ACCEPTANCE>" --title "TITLE"

# a Worker session materializes on demand and claims it via the pi agent hook
gc hook --claim --json
```

Beads are durable; sessions are disposable. A Worker crash leaves the task
recoverable. Manager/Executive sessions resume from Gas City session identity.

### Task bead closure (known behavior)

The Worker closes its task bead with the canonical work-record contract
(`gc.work_outcome=shipped`, ADR-0009 — same as the `mol-do-work` formula);
the Manager closes it on ACCEPT if still open. Both prompts carry the exact
command. Depending on the model, the Worker may instead leave the bead
`in_progress` "awaiting review" — the durable work record (work_dir, commit)
is still complete and the Manager reviews it. Until a task bead is closed,
`gc hook --claim` keeps returning it as the session's existing assignment,
so new work waits: close the bead (Worker, Manager, or `gc bd close <id>`)
to unblock. This is model-variant behavior, not a Gas City defect.

## Secrets

This repository is public. Machine-local state (`.gc/`, `.beads/` runtime,
rig paths in `.gc/site.toml`) is gitignored; only `.beads/identity.toml`
is committed. Pi authenticates via `~/.pi/agent/auth.json`, never in-repo.
