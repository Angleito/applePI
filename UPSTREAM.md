# Upstreams and Pins

This harness consumes three sources. Only two are ever modified.

## Gas City — pinned, never forked

| Item          | Value                                                        |
| ------------- | ------------------------------------------------------------ |
| Repository    | https://github.com/gastownhall/gascity                       |
| Release       | **v1.4.1** (2026-08-15)                                      |
| Release SHA   | `58ef17e3bd685fd5cf7f21286277b208d3324590`                   |
| Install       | `gascity_1.4.1_linux_amd64.tar.gz` (sha256-verified) → `~/.local/bin/gc` |
| Pack pins     | `core` + `bd`, both `sha:f895c0ff…` — the canonical pins written by `gc init` (v1.4.1 bundled pack cache) |
| applePI pack  | `packs/applepi-roles/` — in-repo reusable rig roles; imported per rig via `[rigs.imports.applepi-roles] source = "packs/applepi-roles"` (relative to the city root, so fresh clones resolve it) |

Do not modify Gas City. Consume the pinned release. To bump: update the
release + pack pins together, re-run `gc import install`, and re-run the
integration tests. Pack pins are generated by Gas City's own tooling
(`gc init` / `gc import install`) — never guess a SHA by hand.

## Pi Coding Agent — the only reasoning harness

| Item       | Value                                          |
| ---------- | ---------------------------------------------- |
| Repository | https://github.com/badlogic/pi-mono            |
| Installed  | `~/.local/bin/pi` (0.84.3 at time of writing)  |
| Provider   | `openai-codex` (ChatGPT OAuth; check with `pi auth check --provider openai-codex --model gpt-5.6-luna`) |
| Models     | Pi launcher defaults: `gpt-5.6-terra` (Executive/Manager), `gpt-5.6-luna` (Worker) — configurable in local `.env` |

## pi-interactive-subagents — planned (Amos base)

| Item       | Value                                                       |
| ---------- | ----------------------------------------------------------- |
| Upstream   | https://github.com/amosblomqvist/pi-interactive-subagents   |
| Fork       | **not created yet**                                         |
| Status     | **planned for Phase 5**                                     |
| Base SHA   | **not pinned yet** (record the exact upstream SHA here at fork time) |
| Remotes    | `origin` → fork, `upstream` → amosblomqvist/pi-interactive-subagents (at fork time) |
| Install    | `pi install git:github.com:Angleito/pi-interactive-subagents` (at fork time) |

Planned local modifications (tracked on a `company-control` branch):

1. `PI_SUBAGENT_ENABLED` — when `0`, the extension registers no subagent
   tools. Executive and Manager run with it off.
2. `PI_SUBAGENT_MAX_RUNNING` — caps concurrent subagents per session.
3. Enforce `PI_SUBAGENT_ALLOWED` for top-level sessions (Worker runs with
   `scout`).

Worker environment (declared in `agents/worker/agent.toml`):

```text
PI_SUBAGENT_ENABLED=1
PI_SUBAGENT_ALLOWED=scout
PI_SUBAGENT_MAX_RUNNING=3
```

These variables have **no effect until the fork is installed** — the
upstream extension is not present in this milestone. Do not rely on them.

## Known upstream limitations

- **gastownhall/gascity#1761** — the file-backed beads provider cannot
  auto-claim routed work (work queries are `bd`-only). applePI therefore
  uses the `bd` (Dolt) backend; `city.toml` leaves `[beads]` unset so Gas
  City's default (`bd`) applies. Revisit if the file store gains query
  support.
- **gastownhall/gascity#1938** — `mol-scoped-work` control beads may not be
  claimed by the control dispatcher (open at time of writing). Verify
  before relying on it; the harness has a prompt-driven worktree fallback.
